# Dev Vault Code Guide

Everything in this site is driven by `.mdx` files inside `src/documentation/`. This page explains the folder conventions, how the registry picks up pages, and how to add new ones.

## How it works

1. `registry-server.ts` recursively scans `src/documentation/` for `.mdx` files
2. Each file's path becomes its route — with one deduplication rule (see below)
3. `MDXPage.tsx` holds a static `importMap` that maps each file path to a dynamic import — **every new file must be added here manually**

## Folder & file naming

Pages live at:

```
src/documentation/<section>/<group>/<name>.mdx
```

The registry deduplicates when the filename (without `.mdx`) equals its parent folder name:

```
nextjs-and-reactjs/utils/add-query-params/add-query-params.mdx
→ route: /nextjs-and-reactjs/utils/add-query-params
```

So always name the file the same as its parent folder.

## Adding a new page

Just two steps — no registration needed. `MDXPage` uses a dynamic import with a static prefix so webpack auto-discovers every `.mdx` file under `src/documentation/`.

### 1. Create the file

```
src/documentation/nextjs-and-reactjs/<group>/<name>/<name>.mdx
```

### 2. Add the meta export

```mdx
export const meta = {
  title: "My Page",
  category: "Utils",
  order: 5,
};
```

| Field | Type | Description |
|-------|------|-------------|
| `title` | `string` | Sidebar label and page heading |
| `category` | `string` | Groups pages in the sidebar |
| `order` | `number` | Sort order within the group (lower = higher) |
| `description` | `string` | Optional subtitle |
| `hideFromNav` | `boolean` | Hides the page from the sidebar |

## Doc-ui primitives

### `<Demo>`

Renders a live preview and a copyable code block with a tab switcher.

```mdx
import { Demo } from "@/doc-ui/Demo";
import { Button } from "@/components/ui/Button";

<Demo
  title="My Button"
  code={`<Button variant="outline">Click me</Button>`}
>
  <Button variant="outline">Click me</Button>
</Demo>
```

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `code` | `string` | — | Source shown in the Code tab |
| `children` | `ReactNode` | — | Live rendered preview |
| `title` | `string` | — | Label in the demo header |
| `language` | `string` | `"tsx"` | Syntax highlighting language |
| `defaultTab` | `"preview" \| "code"` | `"preview"` | Which tab opens first |

### `<CodeBlock>`

Source-only block, no preview.

```mdx
import { CodeBlock } from "@/doc-ui/CodeBlock";

<CodeBlock language="ts" source={mySourceString} />
```

### `<Prompt>`

Renders a collapsible markdown prompt block with a copy button.

```mdx
import { Prompt } from "@/doc-ui/Prompt";
import PromptContent from "./my-prompt.md";
import promptSource from "./my-prompt.md?raw";

<Prompt source={promptSource} title="My Prompt">
  <PromptContent />
</Prompt>
```

## Interactive demos with local state

MDX supports exporting React components inline. Use this when a demo needs `useState`:

```mdx
import React from "react";
import { Modal, ModalClose } from "@/components/ui/Modal";
import { Button } from "@/components/ui/Button";
import { Dialog } from "radix-ui";

export function ModalDemo() {
  const [open, setOpen] = React.useState(false);
  return (
    <>
      <Button onClick={() => setOpen(true)}>Open Modal</Button>
      <Modal open={open} onOpenChange={setOpen} className="w-[400px] p-6">
        <Dialog.Title>Title</Dialog.Title>
        <ModalClose />
      </Modal>
    </>
  );
}

<Demo title="Modal" code={`...`}>
  <ModalDemo />
</Demo>
```
